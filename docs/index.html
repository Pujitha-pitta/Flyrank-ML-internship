Content Refresh Opportunity Scoring using Search Intelligence

Author: Naga Pujitha

FlyRank ML Internship Capstone Project

Abstract

This study investigates how search and content performance signals can be used to identify pages that may benefit from content refresh. Using the FlyRank ML Internship dataset, page-level features were created from search visibility, clicks, engagement, freshness, and trend information. A rule-based baseline and a logistic regression model were evaluated on the same validation split, with leakage-prone variables removed before training. The logistic regression model achieved a higher F1-score than the rule baseline, although overall predictive performance remained modest. The final output is therefore framed as a decision-support ranking system that helps teams prioritize pages for review rather than as proof that refreshing content will cause performance improvement.

Introduction and Problem Statement

Content teams often manage thousands of pages and cannot manually review every page with equal attention. Some pages may be declining, stale, underperforming, or showing signs that they should be investigated, while others may be stable or growing and require less immediate action.

The decision supported by this project is: Which content pages should be reviewed first for a possible refresh?

The goal is to create a repeatable scoring and modeling workflow that ranks content pages according to their refresh opportunity. The system does not claim that a refresh will directly cause traffic growth. Instead, it provides evidence-based prioritization so that content teams can focus limited time on the pages most likely to deserve investigation.

Data

This project uses the gated FlyRank ML Internship warehouse release available through Hugging Face. The analysis workflow accessed the data using DuckDB and the hf:// file interface.

The warehouse includes public-safe dimension tables and monthly content performance records. Relevant fields included search impressions, clicks, average position, pageviews, sessions, engaged sessions, scroll events, content age, and freshness-related information.

The analysis used available performance records from January 2025 through June 2025. Data was aggregated to the content-page level before modeling.

Client names, domains, URLs, private search queries, credentials, and raw client exports were excluded. Only anonymized identifiers and safe aggregate performance variables were used.

Methodology

Unit of Analysis

Each row in the modeling dataset represents one content page. Daily and monthly performance records were aggregated to create a page-level dataset suitable for scoring and classification.

Target Definition

The project used a proxy target called needs_refresh_proxy. A page was labeled as needing refresh when its performance trend was classified as declining. Stable and growing pages were assigned to the non-refresh class.

This target is a practical prioritization proxy rather than a verified business outcome. A declining trend may reflect seasonality, changing search demand, competition, or other external factors.

Features

The model used public-safe content and performance signals such as:

  • Search impressions
  • Search clicks
  • Click-through rate
  • Average search position
  • Pageviews and sessions
  • Engagement rate
  • Scroll activity
  • Content age
  • Days since the last update
  • Freshness and content-length indicators

Leakage Checks

Variables directly used to create the target were removed from the feature set. In particular, trend_direction and trend_pct were excluded because including them would allow the model to reconstruct the label and produce misleadingly strong results.

Baseline

A rule-based action score was used as the baseline. The score prioritized pages using interpretable signals such as staleness, click-through rate, average position, impressions, and recent performance weakness.

Model

Logistic regression was selected as the first machine learning model. It provides a simple and interpretable comparison against the rule-based baseline and produces a probability that can be used as a ranking score.

Validation Design

The baseline and logistic regression model were evaluated using the same held-out split. Performance was compared using accuracy, precision, recall, F1-score, and ROC-AUC. F1-score was treated as an important metric because it balances precision and recall and is more informative than accuracy alone when the classes are uneven.

Results

The rule-based baseline and the logistic regression model were evaluated using the same validation split to ensure a fair comparison. Performance was measured using Accuracy, Precision, Recall, F1-score, and ROC-AUC.

Model Accuracy Precision Recall F1-score ROC-AUC
Rule-Based Baseline 0.515 0.628 0.124 0.206 0.524
Logistic Regression 0.534 0.548 0.511 0.529 0.541

Discussion

The logistic regression model outperformed the rule-based baseline, particularly in Recall and F1-score, indicating a better balance between identifying refresh opportunities and avoiding missed cases.

Although the overall performance is modest, the model demonstrates that combining multiple search and engagement signals provides more consistent prioritization than simple rule-based scoring alone.

Rather than serving as an automated decision-maker, the model is intended to rank pages for human review, helping content teams focus on pages that deserve investigation first.

Limitations and Honest Framing

This study is based on observational search and engagement data. The results show associations between page-level signals and the refresh proxy, but they do not prove that refreshing a page will cause higher traffic, rankings, clicks, or engagement.

The target is a proxy based on declining performance rather than a confirmed editorial judgment. Some pages may decline because of seasonality, reduced search demand, technical issues, changing competition, or measurement gaps.

The model performance was modest, so the output should be interpreted as directional decision support. It is designed to help teams prioritize manual investigation, not replace editorial review.

Future work could use longer time windows, grouped validation by client, future-window outcome labels, calibration analysis, and post-refresh evaluation.

Ranked Recommendations

Pages should be ranked using the predicted refresh probability together with clear reason codes. The following action playbook converts the model output into practical recommendations.

  1. Review high-visibility declining pages first. Prioritize pages with strong impressions but weakening clicks, CTR, engagement, or recent performance.
  2. Investigate CTR opportunities. Review titles, descriptions, search intent alignment, and page positioning for visible pages that receive fewer clicks than expected.
  3. Refresh stale pages with continued demand. Update pages that have not been revised recently but still receive impressions, sessions, or user engagement.
  4. Monitor recovering pages before rewriting. Avoid unnecessary changes when recent signals suggest that a page may already be improving.
  5. Protect strong and growing pages. Maintain successful pages, monitor them for future decline, and avoid disruptive edits without evidence.

Example Reason Codes

  • Declining recent performance
  • High impressions with low CTR
  • Stale content with active search demand
  • Weak engagement
  • Average position offers improvement potential
  • Monitor only — recent recovery detected
